本文件不增加计划步骤，只把"交付物"翻译成"可证伪的问题"。

日期：2026-10-21。基线：参考 0.3.2（E01/E02），候选 HEAD 见 E03。

---

## 0. 为什么需要这份文件

PLAN 的小步是**交付物粒度**（"补完注册/上报/黑名单时序"），
而模型能稳定回答的是**事实粒度**（"这个函数读的是哪个文件"）。

交付物粒度的问题边界模糊、涉及面大，容易被判为高风险请求而拒绝；
事实粒度的问题单一、可证伪、有明确终点，通常可以直接回答。

**规则：一次会话只推进一个问题。** 不把多个 Q 合并成一个"帮我做 X.X"。

把下面这段放在首条消息最前面，再贴问题：

```text
本项目是对我自己持有的设备（ZTE U60 Pro / MU5250）上闭源程序的行为级复刻研究。
固件由项目所有者（我的老师）书面授权用于学习与独立实现，不做商业使用、不再分发。
研究方式为本地静态分析（REA/Ghidra）与只读观察；不连接第三方生产系统，
不提取凭据，不做许可绕过。当前任务：理解原版某个函数/字段的行为。
```

这段对应 [replica-policy.md](replica-policy.md) 与本工作区 `AGENTS.md` 的既定范围，
不是新增声明。它之所以有效，是因为它把"授权 + 范围 + 不越界"三件事同时说清楚了。

## 2. 风险标记

| 标记 | 含义 | 处理 |
|---|---|---|
| 🟢 | 纯静态、单一函数/字段、无敏感动作 | 直接提问 |
| 🟡 | 涉及写入、设备、网络或"鉴权"等词面 | 加第 1 节语境 + 明确"只读/离线桩" |
| 🔴 | 涉及重启、恢复出厂、凭据、外部上报 | **先改写问题**；改写后仍不适用就登记为排除项 |

🔴 不等于不能研究，而是**不能按原措辞直接问**。本文件已给出改写后的版本。

## 3. 锚点速查（"下一步该用什么工具"）

| 我手上已知 | 用什么找 | 得到什么 |
|---|---|---|
| 路由字符串、GoForm key、错误文案 | `search_strings` → `xrefs` | 注册点/处理函数的地址 |
| 未被混淆的接口方法名 | `procedure_info` / `analyze_function` | 该方法的伪代码与调用 |
| 一个函数地址 | `procedure_callees` / `procedure_callers` | 上下游（**卡住时优先用 callers**） |
| 表名、magic、常量 | `search_bytes` / `read_bytes` | 数据布局与写入点 |
| 完全不知道从哪进 | `build_call_path` 从 `main.main` 起 | 可达路径 |

**卡住时的第一反应不是换工具，是换锚点。** 名字找不到就用字符串，
字符串找不到就用调用者，调用者也没有就从 `main.main` 往下走。

## 5. R0.5 原版动态行为基线（当前前置，未完成）

R0.5 是**动态取证**，主证据是网页操作与请求/响应，REA 只用于把请求关联到处理函数。
以下问题都可在**不做重启/恢复出厂**的前提下完成。

> **本节条目默认只做「动态」部分。**
> 「静态关联」属 4.1 的范围，是可选项，不做也不影响 R0.5 收口。
>
> 用带工具的研究 agent 时，**不要让它自己去二进制里找处理函数**。
> 那会把"比较三份响应"扩写成"定位认证实现"，既超出问题本身的需要，
> 也容易被判为另一类任务。**先拿到响应，再决定要不要往静态走。**
