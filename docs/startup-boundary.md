# R0.4 启动副作用与兼容验收约定 v1

2026-10-21。依据R0.1—R0.3原版证据，以及用户明确要求的“脚本安装/卸载，不影响原系统”。这是后续实现与验收的约定，不代表表中功能已实现或实机通过。

## 两个目标的边界

功能兼容覆盖原版的用户操作、API、配置语义和后台效果；独立安装使用 `/data/ufi-tools-re`、HTTP 2433。原版 `/data/ufi-tools`、2333和现有插件保持其归属。不能用“完全照搬原版”解释覆盖原目录、清理共享插件或写入原版哨兵。

默认启动只读设备信息。用户明确启用的设备控制功能可以改变目标设置，但必须有前值、读回和恢复用例；“不影响原系统”指装卸与默认启动保护，不是承诺主动修改Wi-Fi等操作没有系统效果。

## 启动与停止契约

| 行为 | 原版事实 | 候选约定 | 必须验收 |
|---|---|---|---|
| 实例路径/端口 | 原目录2333、部分路径硬编码 | 所有入口解析同一实例根；默认安装端口2433；拒绝碰原目录或未知归属路径 | CLI/ADB/LAN/冷启动一致；端口冲突明确失败 |
| namespace | overlay+bind+重执行，失败可降级 | 当前独立模式不自动接管/sdcard；若为插件提供私有视图，使用自有后端，隔离失败不得静默转成宿主写入 | 主进程/子进程视图、失败残留、卸载mount归属 |
| service.sh维护 | 程序启动可重写自身service.sh并删相邻PID | 生命周期由独立安装器管理；程序不悄悄覆盖安装器脚本/PID协议 | 启动前后脚本哈希、PID归属，拒绝停止原进程 |
| 配置A/B | 文件引导和DB运行对象独立 | 保留两份来源语义；实例根是控制面的固定边界，不能由导入DB逃逸；差异需明示 | R0.2用例、文件/DB分叉、环境覆盖、损坏回退 |
| 凭据/身份 | 文件与DB可能各生成默认值 | 候选使用独立身份；迁移仅处理用户授权副本，不提取原版凭据、不复制内置密钥 | 首次初始化、保留设置、失败不重置已有身份 |
| 插件boot | boot ID标记、20秒延迟、先标记后执行 | 默认禁用；启用后保持已确定时序并只访问候选插件/标记/日志目录；运行失败单独记录 | 同次开机多次启动、无脚本、脚本失败、取消、子进程清理 |
| ttyd | 按开关可能自动启动1146 | 默认不抢占原版1146；启用时分配独立端口、认证及子进程归属 | 开关持久化、端口冲突、启动失败、卸载清理 |
| reset哨兵/pending | 写/etc、/overlay公共哨兵 | 使用候选专用名称；正常安装/升级不被判为恢复出厂；suspected不清理 | 初装、普通重启、槽位切换、外来/损坏状态、读失败 |
| reset confirmed | 原版只保留2个普通文件，清空data与共享plugins | 只处理自有数据/插件，保留安装归属与恢复材料；清理前必须有可验证备份和事件记录；失败停止而不伪报成功 | 同一套逻辑只在临时目录/自有实例测试，不可触原系统 |
| reset监视 | 新flag可触发退出，握手停滞可重启模块 | 默认不启动主动重启模块动作；启用后使用已核实模块白名单、上限/取消和事件记录 | 合成握手先验证；设备恢复前单独制定回滚步骤 |
| hosts/USB/校时等 | 启动入口可能写系统 | 默认不开自动写；启用有保存前值、写入归属和恢复规则 | 触发、失败、重复、退出和恢复；禁止仅测HTTP200 |
| 外部服务 | 插件/注册/更新等可能出站 | 研究优先本地模拟服务；未经明确授权不向第三方发真实设备数据、短信或Webhook | 出站目标、字段、重试及失败行为；真实投递另确认 |
| 停机 | context取消、HTTP关闭、defer清理 | 停止新任务、取消工作、等待已知子进程、关闭DB；只清理自有资源 | 信号、请求中断、超时、重复停止、异常后恢复 |

这是一组明确的安装隔离及缺陷修正约定，不能把它们写成“原版本来如此”。不生效的SQLite参数、吞读取错误导致默认覆盖、非事务清理等原版问题作为差异登记，候选采用可恢复实现，并用外部可观察行为说明差异。

## 动态对照的完整链条

每次仅研究一个模块。以同一用例ID串联：

1. 固定原版与候选样本/包哈希、固件、输入、登录状态、插件集合和前置设备状态。
2. 真实点击网页控件，记录页面变化及该动作窗口内的请求方法、路径、脱敏参数、响应、错误与调用发起位置。
3. 用REA将请求路由对应到原版处理函数、后台任务和实际设备调用；不把前端源码当作后端实现。
4. 从设备独立读取设置/进程/文件等结果，确认效果及持久性；恢复前值并复核。
5. 恢复同一前置状态，对候选执行相同操作，比较请求/响应/效果/恢复。只白名单归一化时间、随机ID等已解释字段。

请求成功、页面提示成功、设备生效、恢复成功分别记录。任一环缺失，用例只能是部分完成；候选未实现时记录失败或缺口，不能以模拟器200通过替代。后台、重启、插件和隐藏控件同样需要证据。

## 动态测试分组及执行条件

| 分组 | 范围 | 开始条件 | 结束条件 |
|---|---|---|---|
| D0 公共/未登录 | 首页、登录表单、未授权错误 | 指定目标可访问 | 两侧同操作与网络证据，失败有说明 |
| D1 已登录只读 | 状态、列表、当前配置、历史 | 用户正常登录；不读取明文凭据或私信正文 | 页面→请求→处理链→独立设备读数 |
| D2 可恢复设置 | 昵称、界面设置、合成任务/配置等 | 保存精确前值，自有夹具，恢复路径已验证 | 原版/候选逐项读回并恢复 |
| D3 可中断设备控制 | Wi-Fi/APN/SIM/锁频/USB、重启 | 用户确认可断网；独立ADB控制；记录具体恢复命令和前值 | 断线重连、状态读回、恢复与复核 |
| D4 高影响与外部动作 | 恢复出厂、固件更新、实际消息投递、权限扩大 | 当前可恢复备份、目标范围与具体操作确认；不能用笼统全测替代不可逆步骤确认 | 目标用例全链证据；未满足条件则明确待执行 |

用户已说明更换手机热点、设备可以断网；这满足中断容忍条件，但不代替D4的备份恢复验证。凭据变更等需用户在界面完成的步骤由用户操作，我们只观察脱敏结果。

## 记录与覆盖

使用现有R/U/K/F条目作为范围索引。每个运行记录至少有：用例ID、模块、前置状态、两侧动作、请求/响应文件、原版函数地址/Evidence ID、设备前后结果、恢复结果、差异说明和状态。没有网页动作的API/后台用例明确标注，不冒称按钮点击。

R0.4的完成是本约定和可执行的验收边界已建立；D0—D4逐项执行属于接下来的实际工作。不能因本文件创建就把网页抓包、设备读写或全部差分勾选完成。


## 原版取证与候选验收的先后顺序

2026-10-21按用户纠正，增加R0.5作为3.1前置：

1. **先完成原版动态基线。** 依现有功能矩阵，每次一个模块，记录操作、请求/响应、REA处理链、设备结果与恢复。当前先从D0登录入口开始，再D1、D2及满足执行条件的D3/D4。无法执行的项目保持未完成，不将其默认为通过。
2. **再按3.1起逐模块实现。** 基线中的观察结果和已确认静态规则共同定义预期；实现中遇到新分支，回原版补取证。
3. **每个模块完成后进行候选动态对照。** 重用原版用例、输入和前置状态，比较请求/响应及实际效果。3.1完成只支持配置相关对照，其余模块随对应步骤验收；不能据此宣称全软件兼容。
4. **第6阶段做完整实机回归。** 覆盖装卸、持久性、重启、跨模块和恢复。

原版基线完成与候选兼容通过分别记录。现有coverage-summary.json中的accepted=0是兼容验收状态；后续原版取证需独立统计，不能为表示基线进度而将候选验收项勾选。


## 本轮明确禁止的操作

2026-10-21用户明确要求：研究原版时不要按关机、重启、恢复出厂设置。禁止点击这些入口及确认按钮，也不以API、ADB、shell或定时任务触发等效动作；插件重启、服务重启及恢复类控件本轮同样不操作。不得为补动态覆盖绕过此限制。对应行为仅保留静态证据，动态用例标为用户禁止/未执行，不反复请求开放。当前先做首页状态刷新这一只读模块，保留用户已有登录会话；不点击登录/登出以免退出。
